# 沿海台风实况与分级预警网站项目计划书

版本：1.0　日期：2026-11-15

## 一、项目目标

为沿海居民提供易读、及时、可追溯的台风信息，让用户快速了解“叫什么、在哪里、往哪走、风力多大”，并查看所在地区的官方预警和防御指引。首期采用中文移动端网页，覆盖中国大陆沿海，先选一个具备可靠数据授权的城市试点。

成功标准：在手机首屏看见四项核心信息、发布时间和本地预警；居民无需理解专业地图即可读懂当前状态。无数据、过期和解除状态均明确表达。

## 二、用户与使用场景

- 沿海家庭：查看本地预警，准备防风物资，安排出行。
- 老年居民：通过大字体、明确文字和简洁操作读取信息。
- 外来游客：手动选择当前城市，了解官方防御要求。

默认允许手动选城市；定位为可选功能，经用户同意后使用，首期不存储精确位置。

## 三、首期功能与页面

首页由本地预警卡、台风概况卡、路径地图、来源与更新时间组成。多台风同时存在时可切换，列表优先展示与所选地区相关的台风，并公开排序依据。

| 模块 | 必须展示的信息 | 展示要求 |
| --- | --- | --- |
| 台风名称 | 中文名、英文名、官方编号、强度类别 | 未命名时展示编号，不编造名称 |
| 当前位置 | 中心经纬度、观测时间、官方位置描述 | 坐标与地图一致；城市距离若自行计算须标注估算 |
| 往哪走 | 官方移动方向、移动速度、未来路径 | 速度用公里/小时；方向用中文；预测标明有效时间 |
| 风力多大 | 中心附近最大风速、风力等级 | 风速用米/秒，保留官方口径；不能当作用户所在地风力 |
| 本地预警 | 类型、级别、发布机构、适用地区、发布时间、状态、原文链接 | 与所选行政区匹配，显示更新、解除和失效 |
| 防御指引 | 官方建议与当地通知入口 | 不自行推断停工、停课或撤离决定 |

路径图用实线表示历史中心位置，虚线表示预报路径；显示图例、时间和预报机构。预测路径存在不确定性，不把路径线当作影响边界；没有可靠范围数据时不自行绘制概率圈。地图加载失败仍可阅读所有核心信息。

## 四、分级预警方案

国家层面台风预警信号通常使用蓝、黄、橙、红四级；地方制度可能不同，应保留当地官方级别和原文，支持白色等扩展级别，不强行归并。

| 级别 | 页面表达 | 配套内容 |
| --- | --- | --- |
| 蓝色 | 蓝色图标与“台风蓝色预警”文字 | 展示当地官方防御指引 |
| 黄色 | 黄色图标与“台风黄色预警”文字 | 突出官方更新与防御要求 |
| 橙色 | 橙色图标与“台风橙色预警”文字 | 提升信息优先级，突出适用地区 |
| 红色 | 红色图标与“台风红色预警”文字 | 首屏醒目展示官方指令入口 |

等级只转述授权官方预警，不根据台风中心风力自动生成地方预警。颜色同时配合文字和图标，支持色觉障碍用户。不同机构的预警保留发布层级与适用区域；同一机构同一预警按版本更新时间处理，保存变更记录。无有效预警与预警数据获取失败必须是不同状态。

首期提供网页内预警展示和自动刷新；短信、微信和浏览器推送列入后续阶段，需另行完成订阅授权、送达评估与费用核算。

## 五、数据来源与质量

优先评估中国气象局、中央气象台及地方气象部门的授权数据渠道。公开网页仅作为信息入口，不假定存在可免费调用的接口。开发前确认接口文档、授权、更新频率、再分发权、服务保障和费用。

数据分为台风实况、路径预报、本地预警三类，分别保留来源、观测或发布时间、有效时间、抓取时间与原文地址。各类数据独立更新，不能用抓取时间冒充观测时间。

初步目标为每5分钟检查更新，最终频率遵守供应方限制；预警新版本入库后60秒内在在线页面可见。超时规则按各数据源约定发布周期配置：超过约定周期及容忍窗口即提示延迟，严重过期时取消“实时”标识。历史缓存始终附原始时间，失败不得显示为无台风或无预警。

接入层校验坐标范围、单位、时间顺序、重复记录、异常跳点和预警地区编码；异常进入隔离记录并告警，不静默覆盖已验证数据。备用源单独标注，口径冲突时明确来源，不混合拼接成同一条实况。

## 六、技术实施建议

前端建议使用 TypeScript 与 React，地图选型评估 MapLibre GL JS 及合规底图供应商，提供文字替代视图。后端使用 Node.js 数据适配服务，PostgreSQL 保存标准化记录与预警版本，缓存层减少上游请求。技术版本在实施时锁定。

浏览器通过本项目只读接口访问数据，上游密钥仅保留在服务端。定时任务负责拉取、校验、去重、存储与缓存刷新。统一使用带时区的时间字段，界面默认北京时间。坐标系转换由地图适配层统一处理并验证。

建议实体包括 Cyclone、Observation、ForecastPoint、Warning、SourceStatus；每条记录关联 source_id 和原始记录标识。Warning 额外保留行政区、官方级别、生命周期状态与版本关系。

建议接口：GET /api/cyclones、GET /api/cyclones/{id}、GET /api/warnings?areaCode=、GET /api/source-status。响应带来源时间和质量状态，允许空结果与失败状态分别表达。

## 七、体验与运维

移动端优先，兼容360像素宽度，大字体、高对比度、按钮有明确标签。低带宽时优先加载文本，地图按需加载；不依赖动画传递预警。首期不要求注册。

部署使用 HTTPS、请求限流、密钥管理、错误监测与数据库备份。监测数据新鲜度、抓取失败率、预警更新延迟及接口可用性；设置值班联系人与故障处理流程。目标月可用性99.9%，上线前按预算和供应方能力确认。

## 九、验收标准

1. 台风名称、坐标、移动方向、速度及风力与同一来源同一时刻记录一致，单位和时间清晰。
2. 选定城市只能收到适用该区域的预警；蓝黄橙红、地方扩展级别、升级、降级、解除、过期均有回放验证。
3. 数据源中断、地图失败、无活动台风、多台风与陈旧缓存均显示正确状态。
4. 预报与实况视觉可区分，台风中心风力与本地影响表述可区分。
5. 在约定4G测试条件下首屏核心文本目标3秒内可见；支持键盘操作与文字读取。
6. 邀请至少5名试点居民完成四项核心信息查找，至少4名在30秒内独立完成。
7. 上线前确认授权、来源标识、监控告警、备份恢复与回滚演练完成。

## 十、主要风险与后续规划

数据授权或时效不满足时暂停实时上线，可先用明确标注的历史演示数据验证界面。地方预警规则差异通过地区配置解决；访问高峰通过缓存和静态降级应对。任何衍生影响提示需公开方法并与官方预警区分，首期不提供自动灾损预测或撤离路线。

后续可增加多城市关注、经授权的消息订阅、历史台风查询和官方暴雨/风暴潮信息。风暴潮、海浪等信息须另接权威数据，不能由台风风力推导。
